# Overview

The `workflow` parameter on `conversational_ai.agents.create` / `.update` takes an
`AgentWorkflowRequestModel`. Its Pydantic schema is fully captured in
`types.json`, and yet three rules are enforced by **server-side model validators
that run after deserialization** — invisible in the public schema, and therefore
unknowable to [type extraction](/generation/type-extraction.md) by construction.

If a workflow payload returns `422 value_error`, check these three before
anything else. They were found empirically, by iterating against
`api.elevenlabs.io`, and the full symptom-by-symptom writeup with rejected and
accepted payloads lives in
`docs/workflow-gotchas.md` — this concept records
what the rules *are* and which of them tooling can catch.

# The three rules

| # | Rule | Caught locally? |
|---|------|-----------------|
| 1 | The start node must be **keyed literally `start_node`**. The validator looks it up by key, not by scanning values for `type: "start"`. | No |
| 2 | `forward_condition` requires an **explicit `type:` discriminator** (`llm`, `result`, `unconditional`, `expression`). The Pydantic defaults are not applied to inbound requests. | **Yes** — [`Types.validate!`](/api-contract/types-validator.md) |
| 3 | `forward_condition` **cannot be empty `{}`**. An edge must carry at least one condition; unconditional edges must say `{ type: "unconditional" }`. | No |

Rule 1's symptom (`"Workflow must contain a start node"`) points at
`body.workflow.nodes` and gives no hint that the problem is a key name — a node
keyed `"start"` with `type: "start"` set correctly is still invisible to the
validator. Every edge's `source` must be renamed to match.

# Rule 3 has a gem-side trap

Writing `forward_condition: {}` does not even reach the server as `{}`.
[`deep_compact`](/runtime/omit-and-deep-compact.md) strips empty hashes during
body building, so the key is removed entirely — and the server then reports the
*same* "at least one condition" error for a payload that no longer contains the
field at all. Two different mistakes, one error message.

# Minimal accepted payload

```ruby
{
  nodes: {
    "start_node" => { type: "start", edge_order: ["go"] },
    "done"       => { type: "end" }
  },
  edges: {
    "go" => {
      source: "start_node",
      target: "done",
      forward_condition: { type: "unconditional" }
    }
  }
}
```

Everything richer — tool nodes, `result`-gated branches, `llm`-gated
transitions — builds on exactly these three rules.
